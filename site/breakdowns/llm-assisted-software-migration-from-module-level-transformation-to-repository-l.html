Detailed summary

The study by Zhang, Liu, Zhang, and Liu investigates the use of large language models (LLMs) to automate the migration of entire software repositories from one programming language or framework to another. The authors first classify migration approaches into module‑level transformations (individual classes or functions) and repository‑level integrations (full build pipelines, dependency graphs, and test suites). They surveyed 96 academic papers, extracting a taxonomy that maps LLM usage to specific migration stages: code translation, dependency resolution, build configuration, unit and integration testing, and non‑functional property preservation. The findings show that module‑level transformations achieve high precision and low failure rates, but repository‑level migrations suffer from build unreliability, incomplete behaviour preservation, and loss of performance or security guarantees. The authors identify three critical gaps: (1) requirement support – LLMs lack structured input for functional and non‑functional constraints; (2) agent coordination – multiple LLM agents (e.g., for code, tests, and documentation) need orchestration; (3) cost‑benefit assessment – current studies rarely quantify ROI or compare against manual migration. For enterprise IT, these results highlight that while LLMs can accelerate code conversion, they cannot yet replace human oversight for full project migration. Real‑world implications include the need for robust validation pipelines, explicit requirement modeling, and cost accounting for LLM usage. Enterprises should treat LLM‑driven migration as a hybrid process: use LLMs for rapid prototyping and code skeletons, then employ human reviewers and automated tests to ensure functional parity and compliance with security, performance, and regulatory constraints. The study provides a framework for planning such migrations, suggesting checkpoints for build stability, test coverage, and non‑functional metrics, which can be integrated into continuous delivery pipelines.
