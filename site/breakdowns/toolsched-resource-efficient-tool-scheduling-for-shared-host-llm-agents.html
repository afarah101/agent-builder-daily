ToolSched: Resource-Efficient Tool Scheduling for Shared-Host LLM Agents

Detailed summary

ToolSched is a lightweight multi‑core process controller designed to mitigate resource contention among local large language model (LLM) agents that share a single host. The study deployed ToolSched on a production cluster running several LLM agents that execute shell commands on demand. Each agent first estimates its CPU, memory, and I/O requirements before dispatching a command. ToolSched’s MCP (Multi‑Core Processor) server receives these estimates, queries the host’s real‑time resource state, and schedules the command on an appropriate core or time slice. The evaluation compared three configurations: (1) no scheduling (agents run commands immediately), (2) a naive round‑robin scheduler, and (3) ToolSched. Across a mixed workload of 200 concurrent agents, ToolSched increased overall CPU utilisation by 148% and throughput (commands processed per minute) by 29% relative to the naive baseline. Memory fragmentation was reduced by 22%, and average response latency dropped from 1.8 s to 1.2 s. The study also measured the overhead of the estimation step; it added less than 5 ms per command, negligible compared to typical LLM inference times. For enterprise IT, these gains translate into higher density of LLM services per server, lower hardware cost per inference, and more predictable service levels. The real‑world implication is that organisations running multiple LLM agents on shared infrastructure—such as internal knowledge assistants, code generation bots, or customer‑support chatbots—can adopt ToolSched to avoid CPU starvation and I/O bottlenecks without redesigning their agent code. The approach is vendor‑agnostic and can be integrated with existing orchestration tools like Kubernetes or Docker Swarm by exposing the MCP as a sidecar service. The study demonstrates that a lightweight, estimation‑based scheduler can deliver measurable performance improvements in a production setting, making it a compelling option for IT teams managing shared LLM workloads.
