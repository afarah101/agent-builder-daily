MCP servers can now deliver AI agent skills, changing what companies approve when they connect one

Summary

Anthropic has released Skills support over the Model Context Protocol (MCP) for its Claude and Claude Code models, now available in public beta. MCP is a lightweight, JSON‑based protocol that allows external services to be called from within an LLM prompt, effectively turning the model into an AI agent that can interact with APIs, databases, and other systems. The new Skills feature expands this capability by providing a standardized way for third‑party services to expose their functionality as “skills” that Claude can invoke. For enterprise IT teams, this means that the same LLM can now perform real‑world tasks—such as querying a ticketing system, updating a CRM record, or pulling data from an internal analytics platform—without manual intervention.

The announcement matters because it removes a major friction point in deploying LLMs at scale: the need to build custom integrations for each downstream system. MCP‑enabled skills allow organizations to plug existing APIs into the LLM workflow with minimal code, leveraging Anthropic’s safety and compliance controls. Key vendors and technologies involved include Anthropic (Claude), Microsoft Azure (for hosting LLM workloads), Okta or Azure AD (for identity and access management), and MDM solutions such as VMware Workspace ONE or MobileIron that can expose secure APIs. The broader industry implication is a shift toward “agent‑as‑a‑service” models, where enterprises can rapidly assemble AI agents that respect existing policy frameworks and audit trails. This also pressures other LLM providers—OpenAI, Google, Meta—to standardize on similar protocols to remain competitive.

In practice, organizations will need to evaluate how existing SSO, MFA, and policy engines can expose secure endpoints to MCP. The beta nature of the feature requires careful testing around data residency, audit logging, and rate limiting. As more skills become available, the ecosystem will mature into a marketplace of vetted, policy‑compliant services that can be composed into complex workflows, driving a new wave of automation across IT operations, customer support, and business intelligence.

How to apply

Evaluate

- Inventory all APIs that are currently accessed by internal tools (ticketing, CMDB, HR, finance). - Map current IAM policies (SSO, MFA, least‑privilege scopes) to those APIs. - Assess API security posture: OAuth scopes, rate limits, audit logs, and data classification. - Identify existing MDM/SSO solutions that can expose secure, token‑based endpoints to external services.

Propose

- Build a cost‑benefit model: estimate time saved per support ticket or data retrieval task (e.g., 30 min per ticket × 200 tickets/month = 100 hrs/month). - Quantify risk reduction: fewer manual API calls → lower chance of credential leakage. - Benchmark against current SLA targets; show potential SLA improvement (e.g., 15 % faster resolution). - Include ROI: projected savings vs. cost of MCP integration and staff training.

Tools to consider

- Anthropic Claude (with MCP Skills) – core LLM engine. - Azure API Management or AWS API Gateway – to expose internal APIs securely. - Okta or Azure AD – for SSO and token issuance. - VMware Workspace ONE or MobileIron – for MDM‑based API exposure. - Terraform or Pulumi – for IaC deployment of MCP endpoints. - Splunk or ELK Stack – for audit logging of MCP calls.

Risks to flag

- Technical: API throttling, latency, and error handling in agent workflows. - Compliance: UK GDPR – ensure personal data is not exposed to the LLM; enforce data residency controls. - Operational: Over‑privileged skills could modify critical data; implement fine‑grained access controls. - Vendor lock‑in: Anthropic’s MCP may limit future migration; maintain open‑source fallback options.

Quick win

- Deploy a single MCP skill that pulls incident data from ServiceNow and returns a concise summary to the LLM. - Configure Azure API Management to expose the ServiceNow API with OAuth2 and a dedicated “agent” scope. - Test in a sandbox environment; document success metrics within 30 days.

Long-term play

LONG‑TERM PLAY - Over 6–12 months, build a catalog of vetted MCP skills for core business processes (HR onboarding, finance reconciliation, network inventory). - Integrate skill usage into the organization’s policy engine, ensuring all agent actions are logged and auditable. - Develop a governance framework that includes periodic security reviews, model retraining schedules, and incident response plans for AI‑driven workflows.
