HARP: Training-Free Dual-Profile Agentic Communication for LLM-Based Recommendation

Zhen Tao, Xun Zhou et al. · 3 Nov 2026

Summary

HARP (Hybrid Agentic Retrieval for Personalized Recommendations) addresses a common shortfall in large language model (LLM)–driven recommendation systems: the absence of structured item profiles. Traditional LLM recommender pipelines rely on user‑side structured data (e.g., demographics, past interactions) while treating items as unstructured text. This asymmetry hampers the model’s ability to capture item characteristics, leading to suboptimal relevance. HARP introduces three key components that operate without additional training data. First, it derives a rule‑based item profile by extracting structured attributes from item metadata (e.g., genre, price, brand). Second, it applies a homophily gate during retrieval, filtering candidate items to those whose derived profiles align with the user’s profile, thereby enforcing a similarity constraint. Third, it performs a single‑pass in‑context profile update, allowing the LLM to incorporate both user and item profiles in a single inference step. The authors evaluated the approach on multiple public datasets (MovieLens, Amazon product reviews, and a news recommendation benchmark). Hit@1 improved by 6.9% to 24.0% relative to baseline LLM recommender pipelines that only used user profiles. The lift varied with dataset sparsity and the richness of item metadata, but the gains were consistent across all experiments. For enterprise IT, this demonstrates that significant recommendation quality improvements can be achieved through architectural changes rather than costly model retraining or large labeled datasets. The real‑world implications are twofold: first, organizations can enhance user engagement and conversion rates without investing in new data labeling pipelines; second, the rule‑derived item profiles can be generated from existing catalog metadata, making the solution immediately deployable in e‑commerce, content platforms, and internal knowledge bases. The approach also aligns with privacy best practices, as it does not require additional user data beyond what is already collected.

How to apply

Evaluate

- Inventory existing recommendation stack: identify LLM inference engine, retrieval backend, and metadata sources. - Verify availability and quality of item metadata (structured fields, tags, categories). - Measure current Hit@1, NDCG, and latency metrics to establish a baseline. - Confirm that user profiles are already structured (e.g., demographic, behavioral vectors).

Propose

- Build a cost‑benefit model: baseline Hit@1 vs projected lift (6–24%); translate to expected increase in click‑through or sales. - Quantify latency impact: rule‑based profile generation is O(1); homophily gate adds minimal filtering cost. - Present a phased pilot: 3‑month proof of concept with 10% traffic allocation. - Include compliance checkpoints: no new personal data collection, only metadata transformation.

Tools to consider

- Retrieval: Elasticsearch or OpenSearch for vector search with custom scoring. - LLM inference: OpenAI GPT‑4o, Anthropic Claude 3, or open‑source Llama‑2‑70B deployed on NVIDIA A100 GPUs. - Metadata extraction: Apache NiFi or AWS Glue for rule‑based profile generation. - Orchestration: Kubernetes with Argo Workflows to manage the single‑pass update pipeline.

Risks to flag

- Technical: Over‑filtering by the homophily gate could reduce diversity; monitor diversity metrics. - Compliance: Ensure rule‑derived profiles do not inadvertently expose sensitive attributes; audit for UK GDPR “profiling” thresholds. - Operational: Increased CPU usage for profile generation; provision autoscaling.

Quick win

- Implement a simple rule‑based item profile extractor using existing metadata (e.g., JSON schema) and store profiles in a Redis cache. - Add a homophily score threshold to the retrieval query; test on a 1‑week traffic slice. - Measure Hit@1 improvement; if >5%, roll out to full traffic.

Long-term play

- Integrate the rule‑derived profiles into a continuous data pipeline; schedule nightly updates. - Expand the homophily gate to use learned similarity embeddings, refining thresholds with A/B testing. - Deploy a monitoring dashboard (Grafana) to track recommendation quality, latency, and compliance metrics over 6–12 months.
