RuntimeTickets: Source-Grounded Security Obligations for Agent Skills

Kuiyi Gao, Xue Liu, Bowei He · Academic Institution · 2026-11-02 · Generated 04 Nov 2026, 23:33

Summary

RuntimeTickets is a research effort that tackles the problem of enforcing security obligations for third‑party agent skills—software modules that extend the capabilities of conversational agents or other AI‑driven systems. The authors built a lightweight protocol that intercepts every outbound network request made by a skill, evaluates it against a set of fine‑grained obligations, and records a tamper‑evident log. In their test harness, which included a mix of benign and malicious skills, the system achieved zero missed violations and zero false positives, meaning no attack was overlooked and no legitimate action was unnecessarily blocked. The study demonstrates that it is possible to provide strong runtime enforcement for untrusted code without requiring the skill provider to be trusted or to supply a signed binary. For enterprise IT, this is significant because many modern platforms (e.g., customer‑facing chatbots, virtual assistants, or workflow automation tools) increasingly rely on third‑party plugins or skills to add functionality. Traditional approaches—sandboxing, static code analysis, or vendor trust—are either too coarse or too expensive. RuntimeTickets offers a middle ground: it enforces policy at the moment of execution, records evidence for audit, and can be integrated into existing CI/CD pipelines or runtime monitoring stacks. The real‑world implications are that enterprises can adopt a broader ecosystem of external skills while maintaining compliance with data protection regulations (e.g., GDPR) and internal security baselines. By providing a verifiable audit trail, the protocol also supports forensic investigations and regulatory reporting. In practice, organizations can reduce the attack surface of AI‑driven services, enable rapid feature rollout from external developers, and satisfy auditors that they have continuous monitoring and evidence collection in place.

Tools to consider

- RuntimeTickets protocol (open‑source implementation available on GitHub). - Open Policy Agent (OPA) for policy definition and enforcement. - Falco or Sysdig for runtime anomaly detection. - Elastic Stack or Splunk for log aggregation and tamper‑evident storage. - Kubernetes admission controllers if skills run as containers.

Risks to flag

- Technical: Overhead of intercepting every outbound call may impact latency; ensure the policy engine is horizontally scalable. - Compliance: GDPR requires that evidence logs be tamper‑evident and retained for the period of the data processing activity. Verify that the logging solution meets these requirements. - Operational: Skill developers may attempt to bypass the interception layer; enforce that the runtime environment is hardened (e.g., no privileged containers).

Quick win

Deploy a lightweight interception shim in your existing container runtime that logs all outbound HTTP requests to a central log store. Configure a simple OPA policy that blocks any request to an external domain not in an approved whitelist. This can be achieved in under 30 days and will immediately reduce the risk of data leakage from untrusted skills.

Long-term play

Over 6–12 months, integrate the RuntimeTickets protocol into your CI/CD pipeline: automatically generate obligation metadata for each new skill, enforce policies at runtime, and archive evidence in a tamper‑evident ledger (e.g., using a blockchain or immutable log service). Expand the policy language to cover data classification levels, and align it with your enterprise data governance framework. Conduct periodic red‑team exercises to validate that the policy engine remains effective against evolving attack vectors.
