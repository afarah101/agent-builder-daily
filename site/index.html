SPLASH: Switching Parallel Layouts of Attention with Seamless Handoff for LLM Serving

Chuan Liu, Shuoming Zhang, Zhicheng Li, Qianqi Sun · Academic Institution · 29 Sep 2026

SPLASH lets you change the way an LLM splits its attention workload (tensor, data, or context parallelism) on the fly, matching the mix of short and long requests in real time. It builds a lightweight controller that monitors request patterns and reconfigures the parallel layout without draining traffic or restarting servers. The result is smoother scaling and lower latency across mixed workloads, especially where request lengths shift during a session.

HOW TO APPLY THIS

If you manage LLM serving, here is what to do: 1) add SPLASH’s controller to your inference stack to monitor request length and batch size; 2) configure it to automatically switch between tensor, data, and context parallelism based on defined thresholds; 3) enable zero‑downtime handoff so workers keep processing while the layout updates. This flags a risk: if your org uses a static parallelism setting, check whether the request mix varies over time and consider adopting SPLASH to avoid performance dips.

CounterSteer: Suppressing Indirect Prompt Injection with Activation Steering

Mark Russinovich · Academic Institution · 29 Sep 2026

CounterSteer blocks an LLM from acting on untrusted text that looks like instructions, preventing indirect prompt injection. It builds an inference‑time filter that learns a direction to subtract from model outputs, using only a few examples and no fine‑tuning. The result is a safer model that ignores malicious instruction cues while still performing normally.

HOW TO APPLY THIS

If you manage cloud infrastructure, check whether your LLM‑based services might feed untrusted data as tool results; if so, apply a CounterSteer‑style vector subtraction to each response to block indirect instructions, following the three‑step recipe: (1) generate paired episodes with and without embedded instructions, (2) learn the residual direction and gate it, (3) subtract the direction from every token during prefill. This reduces injection risk without extra training.
