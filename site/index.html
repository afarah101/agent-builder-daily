EdgeAgent: Orchestrating On-Device LLM inference for End-User Multi-Agent Systems on CPU-GPU Unified Memory Architectures

Yuhai Long, Yuanxin Wei, Kai Wu, Jinhui Wei · Academic Institution · 02 Oct 2026

EdgeAgent tackles the problem of poor CPU‑GPU co‑execution on unified memory systems when running large language model agents. It orchestrates on‑device inference to minimise bus contention, manage speculative decoding variance, and reduce tool‑induced stalls, leading to higher overall throughput and better hardware utilisation. This directly impacts cloud infra that hosts LLM workloads on edge devices.

HOW TO APPLY THIS

If you manage LLM inference on edge CPUs and GPUs, 1) profile your memory traffic to spot bus contention, 2) deploy EdgeAgent or a similar orchestrator to schedule CPU/GPU work, 3) monitor throughput and adjust speculative decoding settings to keep GPUs busy.

FrugalEvo: Towards Cost-Aware LLM-Guided Program Evolution

Hui Chen, Xuan Qi, James Xu Zhao, Zhaopeng Feng · Academic Institution · 02 Oct 2026

FrugalEvo tackles the high cost of using large language models for automated code evolution by splitting the job: a powerful, expensive LLM designs strategies while a cheaper LLM implements and refines the code, saving money while still improving performance. The team built a dual‑LLM framework with a cache‑efficient evolution loop and showed it delivered better results for optimisation tasks with fewer expensive model calls. This approach is relevant if you run AI‑powered development workflows in the cloud, as it can reduce compute spend and speed up deployment cycles.

HOW TO APPLY THIS

If you manage cloud infrastructure that uses LLMs for code generation, step 1: benchmark the cost per inference of your current LLM; step 2: set up a two‑tier system where a small LLM handles routine code changes and a larger LLM is called only for high‑impact strategy decisions; step 3: monitor the overall inference cost and performance gain to ensure the split remains cost‑effective.

Metropolis-Hastings Dominates Importance Resampling for Policy Composition

Alexey Kurennoy, Ramil Yarullin, Fergal Reid · Academic Institution · 02 Oct 2026

The paper tackles the bias that arises when mixing different reward‑driven policies at decoding time in large language models. The authors propose using a Metropolis‑Hastings (MH) correction instead of the usual next‑token combination, and show that MH outperforms importance resampling. The result is a more accurate way to combine policies for better trade‑offs without retraining the model.

Passing the Test You Trained On: Re-evaluating Prompt-Injection Detectors for LLM Agents

Zhuowen Liu · Academic Institution · 02 Oct 2026

The study shows that detectors chosen based on public benchmarks may not reliably catch prompt‑injection attacks inside real LLM agents. Researchers replayed tool outputs without an LLM to compare fifteen detectors and found that rankings often differ when the detectors are used in practice. The work highlights a mismatch between benchmark performance and real‑world effectiveness, offering a new evaluation framework.

HOW TO APPLY THIS

If you manage cloud‑based LLM deployments, test your chosen prompt‑injection detector against a replay‑based benchmark: 1) generate benign tool outputs, 2) inject malicious prompts manually, 3) measure detection rates; if your detector fails, replace it with one that scores well in the replay evaluation.

ServeTwin: A Benchmark-Validated Simulator for Distributed LLM Architecture Exploration

Sungjoon Park, Changue Jung, Kyungno Joo, Mincheol Kang · Academic Institution · 02 Oct 2026

Evaluating distributed LLM serving designs on real clusters is expensive and existing simulators miss key features like stateful closed‑loop behaviour and full benchmark support. The authors built ServeTwin, a simulator that combines analytical timing with a stateful serving loop, accurately modelling request flow, queue dynamics, and KV‑cache changes. The result is a low‑cost tool that lets designers predict performance and optimise scheduling without hardware trials.

HOW TO APPLY THIS

If you manage a distributed LLM infrastructure, use ServeTwin to model your deployment: 1) define your architecture in the simulator’s spec, 2) run full benchmarks to get timing predictions, 3) analyse queue and cache dynamics to tweak scheduling or resource allocation.
