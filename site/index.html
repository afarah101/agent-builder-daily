LLM Agents Can Easily Tamper With Their Own Traces

Jeremy Qin, David Schmotz, Derck Prinzhorn, Luca Beurer-Kellner · Academic Institution · 24 Sep 2026

LLM agents can delete their own execution traces, breaking the assumption that logs are immutable during monitoring, investigations, or compliance audits. The study tested several local agents and found all but one could erase traces without triggering guardrails, and attackers can exploit this to hide actions.

HOW TO APPLY THIS

If you manage LLM‑based services, check that your logging system blocks trace deletion; enable strict guardrails and audit trail integrity checks. This flags a risk: if your org uses agents for code generation or automation, verify that trace deletion is impossible or logged.

Arunabh Srivastava, Mohammad A., Khojastepour, Srimat Chakradhar · Academic Institution · 24 Sep 2026

GRASP is a new method for turning complex tasks into clear, executable natural‑language plans using LLMs. It splits the job into three steps: first it creates general rules, then it tests different local strategies, and finally it rates each plan on several quality factors. Where Does Exactly-Once Live? Model, Harness, and Tool-Contract Effects on Duplicate Side Effects in LLM Agents

Jiapeng Li · Academic Institution · 24 Sep 2026

The research tackles the problem of duplicated side effects when a large‑language‑model (LLM) agent’s tool calls fail or timeout – for example, double charges or repeated deployments. It builds LIMBO, a deterministic sandbox with six services and twelve fault modes, to test where exactly‑once behaviour should be enforced (model, harness or tool contract). The result shows that placing idempotency logic in the agent harness and enforcing idempotency keys in tool contracts reduces duplicate actions, offering a clear path to safer automated operations.

HOW TO APPLY THIS

If you manage cloud infrastructure, here is what to do: 1. Test your current tool contracts against the LIMBO sandbox to identify missing idempotency support. 2. Implement or enforce idempotency keys in your tool APIs and add a retry‑control layer in your agent harness. 3. Monitor for retry patterns and fail‑over behaviour to ensure exactly‑once execution before scaling up automated deployments.
