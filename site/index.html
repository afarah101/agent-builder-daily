FragToken: Amplifying LLM Inference Costs through Noncanonical Token Generation

Zihan Wang, Rui Zhang, Xinyuan Qian, Qingchuan Zhao · NYU · 25 Sep 2026

This research shows a new way to trick LLM services into spending a lot of compute by making the model output the same text but in many more tokens using non‑canonical token sequences. The authors built a technique that silently inflates token usage and found it can raise inference costs by a large factor while staying hidden from typical monitoring. It matters if you rely on paid LLM APIs and could cost your budget more than expected.

HOW TO APPLY THIS

If you manage cloud LLM usage, check your tokenisation pipeline: enforce canonical token outputs, limit per‑request token counts, and audit token logs for unusually high token counts per identical text.

Raluca Rilla, Anne-Marie Nussberger, Rui Mata, Dirk U. Wulff · Academic Institution · 25 Sep 2026

The study shows that inexpensive, open‑weight LLMs running on open‑source agent frameworks can autonomously inject synthetic responses into survey data, a problem called LLM pollution. The authors tested nine agent setups—some fully open, some commercial—and found that fully open agents could complete surveys with a high success rate while remaining hard to detect. This demonstrates that any organisation running such agents on cloud infrastructure could inadvertently compromise data integrity.

HOW TO APPLY THIS

If you manage cloud infrastructure that hosts or runs LLM agents, check that all agent code is signed and sourced from trusted vendors; implement monitoring for unexpected synthetic data patterns; and consider restricting open‑weight models from accessing sensitive datasets.

DynBranch: Speculative Subgraph Reuse for Dynamic Agentic LLM Serving

Junyi Shen, Noppanat Wadlom, Zhengyuan Su, Yao Lu · Academic Institution · 25 Sep 2026

DynBranch tackles the problem of slow, serialized agentic LLM workflows by allowing parts of a computation graph to be prepared and cached before the decision point is known. The authors built a system that assigns stable coordinates to unresolved branches, enabling subgraphs to run early and reuse results in later requests, which cuts latency and improves throughput. This offers a concrete optimisation for cloud‑hosted LLM services.

HOW TO APPLY THIS

If you manage LLM inference on the cloud, here is what to do: 1. Identify points in your agentic workflow where a decision branches. 2. Integrate a coordinate system that tags each potential branch path before it resolves. 3. Enable early execution of those tagged subgraphs so that when a branch resolves, you can pull from cache instead of recomputing.
