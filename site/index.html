Report: Progressive Disclosure of Agent Skills

Guilin Zhang, Kai Zhao, Priyanka Mudgal, Waleed Ammar · Academic Institution · 28 Sep 2026

When LLM agents grow their skill library, the cost of keeping all skills loaded rises. The authors tested progressive (lazy‑loading) of skills and found it improves the quality of skill retrieval while keeping operational costs lower. This is directly relevant if you run LLM‑powered services in the cloud.

HOW TO APPLY THIS

If you manage LLM agents, 1) set up a skill registry that supports lazy‑loading; 2) configure the agent to request a skill only when needed and cache it for the session; 3) monitor cost and retrieval latency to ensure the benefits outweigh any extra request overhead.

Tracekit: Tamper-Evident Intent-Reasoning-Action Auditing for Autonomous Coding Agents

Bravish Ghosh · Academic Institution · 28 Sep 2026

Tracekit records three logs – the user’s intent, the model’s self‑reported reasoning, and the actions actually carried out – and stores them in a hash‑chained ledger that can be anchored externally, preventing tampering. The system hooks into Claude Code’s events to build a hierarchy of agent interactions and gate tool usage with pre‑checks. This gives an auditable, tamper‑evident trail for autonomous coding agents.

HOW TO APPLY THIS

If you manage cloud infrastructure that runs autonomous coding agents, step 1: integrate Tracekit into the agent lifecycle to capture intent, reasoning, and actions; step 2: configure the hash‑chained ledger to anchor logs to an external, immutable store (e.g., a blockchain or S3 bucket with versioning); step 3: set pre‑checks for tool calls to ensure only authorised commands execute and monitor the ledger for anomalies.

When Valid Tool Calls Change Meaning: Formation-Consistent Dispatch for LLM Agents

Geonwoo Kim, Brent ByungHoon Kang · Academic Institution · 28 Sep 2026

When an LLM agent calls a tool, the same call can later be executed with a different implementation, creating a security gap known as schema‑epoch drift. The authors propose Formation‑Consistent Dispatch (FCD) to tie the tool’s implementation to its declared effect, providing provenance‑bound safety checks. This approach ensures that any tool call used in cloud‑managed services remains consistent and secure across updates and deployments.

HOW TO APPLY THIS

If you manage LLM‑enabled cloud services, adopt FCD by: 1) mapping each tool to its authorised implementation; 2) validating every call against this map before execution; 3) auditing changes to tool definitions for drift risks.
