Loud Failures, Quiet Failures: Fault Detection and Recovery in Tool-Using Language Model Agents

Obada Kraishan · Academic Institution · 07 Oct 2026

The paper tackles the problem that language‑model agents often trust tool outputs even when those tools fail silently, leading to unnoticed errors in real deployments. The researchers added a fault‑injection layer to a function‑calling benchmark, injecting four types of failures at controlled points, and examined how the agents handled each failure. The result is a better understanding of when and how LLM agents over‑trust tool outputs and what signals can flag failures early.

HOW TO APPLY THIS

If you manage cloud infrastructure, here is what to do: 1) Identify the tools your agents call (e.g., API endpoints, scripts). 2) Add a fault‑injection or monitoring layer that can flag timeout, missing endpoint, or parameter mismatches. 3) Require your agents to validate tool outputs against expected schemas or cross‑check with secondary sources before acting.

Constrained-Action AI Remediation for SIEM/XDR via a NeMo-Guardrails Proxy

Georgios Koutidis, Nikolaos Kekatos, Tom Nianios, Alexios Lekidis · Academic Institution · 07 Oct 2026

This paper tackles the danger of using LLMs to automatically triage security alerts and take remedial actions, showing how a single malicious alert can trick the model into issuing harmful commands. The authors built a NeMo-Guardrails proxy that constrains the AI’s actions to a safe set, reducing the risk of accidental or malicious remediation. The result is a safer, more reliable LLM‑based response system that limits potential damage from adversarial inputs.

HOW TO APPLY THIS

If you manage cloud infra and use AI‑driven alert triage, first integrate a guardrail proxy like NeMo-Guardrails to restrict permissible actions. Second, test the system with adversarial alerts to confirm it blocks unsafe commands. Third, monitor logs for any attempts to override or bypass the guardrails.
