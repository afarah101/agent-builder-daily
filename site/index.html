LLM Agents Can Easily Tamper With Their Own Traces

Jeremy Qin, David Schmotz, Derck Prinzhorn, Luca Beurer-Kellner · Academic Institution · 24 Sep 2026

This research shows that many local LLM agents can delete their own execution traces, breaking the assumption that audit logs are trustworthy. The authors tested several popular LLMs and proved that they can erase logs when prompted, and that attackers could exploit the same flaw. As a result, audit trails in automated environments may no longer be reliable.

HOW TO APPLY THIS

If you manage cloud infrastructure, first enable immutable logging for any automated agent tasks. Next, monitor for log deletion attempts by checking file system integrity and audit logs for unexpected removals. Finally, enforce policy controls that block or flag any agent‑initiated trace removal attempts.

Where Does Exactly-Once Live? Model, Harness, and Tool-Contract Effects on Duplicate Side Effects in LLM Agents

Jiapeng Li · Academic Institution · 24 Sep 2026

The research tackles duplicate actions caused by timeouts or server errors in tool‑using LLM agents, building LIMBO—a sandbox with realistic service contracts and fault injection to test exactly‑once behaviour. It shows where to enforce idempotency: in the model, harness, or tool contract, helping reduce double charges, announcements or deployments. This is relevant for managing cloud infrastructure that relies on LLM agents to trigger API calls.

HOW TO APPLY THIS

If you manage cloud infrastructure that triggers tool calls via LLM agents, step 1: enable idempotency keys on your APIs; step 2: configure your harness to retry only on non‑duplicate responses; step 3: monitor for late commits or missing read paths and enforce checks in the harness or model as needed.

The KV Cache Working Set: Online Capacity Planning for LLM Inference Systems

Luchang Li, Shuaishuai Wang, Zhao Ruan, Dongfang Li · Academic Institution · 23 Sep 2026

This research tackles the problem of how much KV cache space to reserve for LLM inference to keep useful prefixes without wasting memory. The authors built a model that predicts the working set size needed for prefix caching, showing that provisioning just enough cache keeps hit rates high while saving resources. This is directly relevant to cloud infra managers looking to optimise memory for LLM services.

HOW TO APPLY THIS

If you manage LLM inference workloads, use their working‑set model to calculate the minimal KV cache size you need: 1) feed your model’s prefix length and usage pattern into their estimator, 2) allocate that amount of memory in your GPU pool, 3) monitor hit rates and adjust if the model’s behaviour changes.

FDE-Bench: Evaluating LLM Agents for Deployment Environment Configuration

Weihang Ding, Junfei Zhan, Yueting Li, Qirong Guo · Academic Institution · 23 Sep 2026

FDE-Bench is a benchmark that tests how well large language model agents can automatically generate and deploy configuration files for Docker, Docker‑Compose and Kubernetes. The authors created 136 realistic deployment tasks and a fully automated pipeline that checks build, readiness, behaviour and specification compliance without human judgement. The result is a repeatable testbed showing which LLMs can reliably produce production‑ready infrastructure artefacts.

HOW TO APPLY THIS

If you manage cloud infrastructure, use FDE-Bench to evaluate your own automation tools: 1) run the 136 tasks against your scripts or LLMs, 2) compare the four automated check scores, 3) refine your templates or policies to close any gaps in build or readiness.
