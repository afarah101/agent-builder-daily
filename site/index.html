OnTrack: Real-Time Monitoring and Intervention in LLM Agent Trajectories via Streaming Structure-Aware Optimal Transport

Babak Barazandeh, Connor Swanson, Chinmay Kulkarni, Nikhil Mungel · Academic Institution · 08 Oct 2026

OnTrack provides a live monitoring system that watches an LLM agent’s actions as they happen, using a structure‑aware optimal transport model to detect deviations from a safe plan. It builds a streaming comparison engine that flags risky moves in real time, allowing immediate corrective intervention. The result is reduced cost and safety risk because problems are caught before irreversible actions are taken.

HOW TO APPLY THIS

If you manage cloud infrastructure, here is what to do: 1) integrate OnTrack into your LLM‑driven incident triage pipeline to monitor agent decisions as they occur; 2) set up alerts for any step that deviates from the expected safe path; 3) configure a fallback script that automatically halts or corrects the agent when a risky deviation is detected.

SparseDecoding: Decoding-Aware Pruning for Accurate and Efficient LLM Inference

Qitong Wang, Xinwei Niu, Mingluo Su, Shanwei Zhao · Academic Institution · 08 Oct 2026

The paper tackles the latency of LLM decoding by pruning weights based on a Hessian calculated during decoding, reducing memory reads. The authors built a pruning method that re‑computes the Hessian on the model’s own generated tokens, avoiding distribution shift and achieving faster inference with little loss of accuracy. This is directly relevant to cloud infrastructure managers who run LLMs, offering a way to cut inference costs and improve throughput.

HOW TO APPLY THIS

If you manage LLM inference, 1) add a Hessian‑aware pruning step before deployment, 2) use the model’s own generated tokens to compute the Hessian during a short calibration run, 3) prune weights and re‑deploy the slimmer model to cut memory bandwidth and latency.

The Harness as the Only Mutable Surface: Compliance-Bounded Self-Evolution of LLM Agents in Credit Pipelines, with a Measured Admission Gate

Ravil Akhtyamov · Academic Institution · 07 Oct 2026

The paper proposes a system that lets large language model (LLM) agents adapt to changes in credit rules without rewriting the core model. They built a dual‑loop engine that confines self‑modification to a runtime harness—just the instruction text, tool‑calls, and primitive composition—while keeping model weights fixed. The result is a safe, traceable way to evolve the agent with an admission gate that records a hash‑chained change log and a test before deployment.

HOW TO APPLY THIS

If you manage cloud infrastructure for AI services, here is what to do: 1) isolate LLM changes to a runtime harness so that the core model weights stay immutable; 2) implement an admission gate that hashes the harness changes, stores the hash chain, and runs automated tests before rollout; 3) ensure every change has an associated diff, cause, and test record for audit purposes.
