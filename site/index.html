CPU-ARC: Agentic Reasoning Caching for on-CPU Reasoning Reuse

Peter Belcak, Greg Heinrich, Saurav Muralidharan, Shizhe Diao·06 Nov 2026

CPU-ARC turns large‑language‑model (LLM) reasoning into reusable, cheap CPU code, giving almost the same accuracy for maths and science problems while cutting cost by 16‑to‑291×. It builds a cache of executable reasoning traces that can be re‑used for new inputs. The result is a robust, explainable, continuously trainable system that is far cheaper than calling the original LLM.

How to apply: If you manage cloud infrastructure, here is what to do: 1. Export your LLM’s reasoning traces to a CPU cache (ARC). 2. Deploy the ARC on your on‑prem or edge nodes. 3. Replace expensive LLM calls with ARC invocations, cutting compute cost and improving latency.

Aligning, Fast and Slow: A Control-Theoretic Oversight Framework for Long-Horizon Trajectories and Maintained Deployments

Stephen Peng, Vineet Jagadeesan Nair, Noah Broestl, Anne Friederike Kleppe·05 Nov 2026

The research presents a two‑level control system for AI agents: a fast loop that approves each action and a slow loop that reviews lasting changes to memory or code. They built this framework and showed that splitting review effort between the two loops cuts worst‑case drift from intended behaviour by about twelve times, and reduces error severity in practical stress tests. This is relevant if you run or monitor AI‑driven services in your cloud infrastructure.

How to apply: If you manage AI‑enabled cloud services, here is what to do: 1) Implement a fast, per‑action approval gate that checks each request before execution; 2) Add a slow, periodic audit that re‑examines any persistent changes (e.g., configuration updates, model retraining) and re‑validates system state; 3) Allocate review resources between the two loops based on the bound derived in the paper to minimise worst‑case drift.

GuardrailAgent: An Agentic Framework for Jailbreak Defense

Tianze Chang, Junjie Chu, Yixin Wu, Michael Backes·06 Nov 2026

GuardrailAgent is a multi‑agent system that automatically learns new jailbreak attacks on large language models and updates its detection rules in real time. It builds an adaptive knowledge base that flags suspicious input and output, improving overall detection to 93.9% and F1 to 95.8% on tested attacks. For IT infrastructure managers, this offers a way to keep LLM‑based services safe without manual rule tweaking.

How to apply: If you run LLM services, integrate GuardrailAgent: 1) Deploy its input‑side filter as a pre‑processing step in your API gateway. 2) Enable the output‑side monitor to flag risky responses before they leave your network. 3) Periodically review the knowledge base updates and adjust your internal policy rules to stay ahead of new jailbreak tactics.

When Routine Operations Break Architectural Pattern Relationships in LLM Agent Harnesses

Boming Xia, Qinghua Lu, Dino Sejdinovic, Liming Zhu·06 Nov 2026

This research shows that routine tasks in LLM agent harnesses can silently break critical architectural relationships, causing policy failures or unsafe actions without any code changes. The team analysed five pattern relationships across five harnesses and 14 plugins, finding that operations like plugin reapplication or rule saving can stop guardrails from evaluating edits. The outcome highlights that architects must check pattern relationships against real operation sequences to avoid silent failures.

How to apply: If you manage LLM agent harnesses, check that routine operations (e.g., reapplying plugins or saving rules) don’t alter the order or state required by Guardrail Enforcement, Autonomy Controller, or Blackboard patterns. Map each operation to the pattern it affects and test whether the guardrails still trigger. If you use a different architecture, the findings may not directly apply.
