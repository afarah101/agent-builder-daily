InferD: A Honeypot Framework for AI Inference Infrastructure

Hicham Hammouchi, Gabriele Lenzini·29 Oct 2026

InferD is a honeypot framework that lets security teams study how AI inference services are attacked without risking real models or data. It emulates the visible behaviour of LLM APIs, vector stores and orchestration gateways, while all responses come from static pools and no actual inference runs. The result is a low‑interaction trap that provides evidence of attack paths and credential use without exposing real assets.

How to apply: If you manage AI inference infrastructure, add InferD to your security stack: 1) deploy the framework on a separate test environment, 2) configure it to mirror your production API endpoints, 3) monitor the static response logs for malicious activity and adjust firewall rules accordingly.

The Real Cost of Context: Predicting Compute Time and Energy Consumption in LLM Prefill and Decode Phases

Lars Krupp, Daniel Geißler, Francisco M. Calatrava-Nicolas, Stefan Gerd Fritsch·29 Oct 2026

This research shows how the energy used by LLMs grows with both the input (prefill) and output (decode) tokens, giving clear scaling rules and a simple way to estimate energy from compute time. It builds a profiling tool and statistical models that map token lengths to compute time and energy, proving that compute time is a good stand‑in for energy when measurements are hard to get. The result is a practical framework that can help you predict and reduce the energy footprint of your LLM workloads.

How to apply: If you manage cloud infrastructure, here is what to do: 1) use the authors’ profiling method to benchmark your LLM workloads and capture prefill and decode token counts; 2) apply the linear/quadratic scaling equations to estimate compute time and energy; 3) adjust your deployment (e.g., limit context length or batch size) to stay within energy budgets and improve sustainability.

When Relevant Code Is Wrong: Runtime-Aware Context for AI Coding Agents

Wesley K. G. Assunção, Ramesh Periyathambi·28 Oct 2026

This research tackles the problem of coding agents misusing older code that no longer runs because of feature flags or architectural changes. The authors built CASE, a framework that links repository code to current runtime settings, classifying artifacts as valid or invalid for guidance. The prototype showed it can filter out 16 previously misapplied artifacts while keeping all applicable ones, proving the idea works but not yet improving agent accuracy.

How to apply: If you manage cloud infrastructure, check your code‑retrieval tools: 1) Integrate runtime metadata (feature flags, deployment configs) into your search queries; 2) Filter out artifacts flagged as invalid by your context‑aware system; 3) Verify that remaining code matches current environment before use.

TextSeal2: Distortion-Free LLM Watermarking with Copula Mixing and Memoryless Races

Tom Sander, Pierre Fernandez, Itai Gat, Haiming Bao·29 Oct 2026

TextSeal2 is a watermark that lets you recognise AI‑generated text without hurting model speed or quality. It merges multiple keys into one, keeping the signal clear even when the model uses speculative decoding. The result is higher detection rates (8‑22% better) with no extra latency. This is relevant to anyone who needs to prove text authenticity in a cloud‑hosted LLM service.

How to apply: If you manage cloud‑hosted LLMs, enable TextSeal2 by: 1) merge your existing watermark keys with a Gaussian copula in the model’s post‑processing; 2) adjust your inference pipeline to run the extra exponential race only on draft leftovers; 3) monitor detection metrics to confirm no latency increase.
