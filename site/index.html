Separating Thinking from Spelling for Efficient Generative Recommendation

Danil Gusak, Anna Volodkevich, Ivan Oseledets, Evgeny Frolov · Academic Institution · 23 Oct 2026

Deco cuts the compute needed to generate recommendation candidates by separating the semantic ID lookup from the heavy decoding step, reducing the number of backbone token passes from O(BK) to a smaller, more efficient operation. The research built a prototype system that achieves faster beam‑search for recommendations while maintaining quality, showing measurable speed‑ups and cost reductions on large‑scale web platforms. For a typical cloud infra manager, this means lower compute usage and faster response times for recommendation services.

HOW TO APPLY THIS

If you manage recommendation workloads, 1) evaluate whether your current model uses beam‑search that scans full semantic IDs; 2) switch to a Deco‑style pipeline that decouples ID look‑up from backbone decoding; 3) monitor CPU/GPU utilisation and latency – you should see a drop in decoding token count and faster candidate generation.

Advancing SVD-based LLM Compression via Layer-Wise Error Model Search

Moritz Thoma, Maximilian Groezinger, Maximilian Forstenhäusler, Emad Aghajanzadeh · Academic Institution · 23 Oct 2026

The research tackles two problems with low‑rank SVD compression of large language models: it improves how ranks are assigned to each layer and fixes the rank collapse caused by traditional Fisher estimators. By adding a layer‑wise error model (LEMS) and a new KFAC‑SVD method, the authors achieve better accuracy‑cost trade‑offs than previous techniques. The result is a more efficient, accurate compressed model that uses fewer compute resources.

HOW TO APPLY THIS

If you manage cloud infrastructure for LLM deployments, 1) evaluate whether your current compression pipeline uses global rank allocation; 2) implement the LEMS layer‑wise error estimator to adjust rank per layer; 3) integrate KFAC‑SVD to avoid rank collapse and test the model’s inference cost on your existing GPU clusters.

Green Code or Costly Code? Evaluating the Energy Costs of Iterative LLM-Based Code Optimizations

Sadra Emami, Benjamin Weigell, Mohammad Reza Mousavi, Gunel Jahangirova · Academic Institution · 23 Oct 2026

The study shows that using LLMs to auto‑optimize code can raise the overall energy bill, even if the resulting code runs faster. Researchers built a self‑refinement pipeline, tested 11 models on a set of tasks, and found that the extra compute cost of the optimisation often outweighs the runtime savings. This matters to cloud managers because it flags a potential hidden cost when deploying LLM‑based optimisation tools.

HOW TO APPLY THIS

If your org uses LLM‑based code optimisation, immediately measure the energy cost of the optimisation pipeline versus the runtime savings of the final code. Compare the energy per run with the baseline; if the optimisation cost is higher, consider disabling or throttling the feature.
