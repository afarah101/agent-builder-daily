When Cache Pressure Becomes a Trap: Metastability in Agent Serving

Chengzhi Lu, Boxi Zhou, Yanying Lin, Dmitrii Ustiugov·MIT·02 Nov 2026

Large‑language‑model (LLM) servers can suffer a long‑lasting slowdown after a brief traffic spike, because the cache used to reuse conversation prefixes collapses and the system keeps working on stale requests. The authors built a tool called Basin that prioritises sessions, pre‑allocates cache for expected peak sizes, and drops excess load, restoring high throughput quickly. On real hardware Basin improved goodput by up to 3.6× compared with earlier cache‑first approaches.

How to apply: If you manage LLM inference servers, check whether your cache policy can collapse after a spike: 1) monitor cache hit rates during short surges, 2) enable a priority‑based admission controller like Basin to reserve peak context sizes, 3) consider shedding low‑priority sessions when cache utilisation exceeds a threshold.

Gabriele Oliaro, Jaeseong Lee, Zhaoyuan Su, Sreeram Vennam·02 Nov 2026

KernelSeek is a question‑driven coding agent that improves CUDA kernels without needing expert knowledge, achieving up to 1.46x speedups on FlashAttention workloads. It uses short, well‑timed questions to steer optimisation, outperforming traditional scripted or open‑ended agents. This is relevant to cloud infrastructure teams that run GPU‑based workloads, offering a way to auto‑optimise kernels for better utilisation of GPU resources.

Ziqi Pang, Yu-Xiong Wang·02 Nov 2026

The researchers solved the problem by training the model on additional bijective tasks, which kept the correct reasoning strategy active even on out‑of‑distribution tests. As a result, the model’s accuracy under harder conditions improved significantly.

Towards a Trustworthy and Governable Internet of Agentics: An Architectural Perspective on Protocols, Systems, and Services

Haoyi Xiong, Yi Liu, Jiang Bian, Peng Diao·02 Nov 2026

The paper proposes a new framework called the Internet of Agentics (IoA) to make large language model agents interoperable, governable, and trustworthy across different systems. It introduces a protocol stack (MCP, A2A, AGENTS.md, etc.) and system abstractions (orchestration, gateways, registries) to treat agents as service components. The result is a clearer pathway for deploying multi‑agent workflows in a controlled, secure, and scalable way.

How to apply: If you manage cloud infrastructure, here is what to do: 1. Evaluate your current agent deployments against the IoA protocol stack (MCP for tool calls, A2A for agent‑to‑agent coordination). 2. Implement or adopt gateways and registries that expose agent services, enabling discovery and orchestration across your cloud environment. 3. Set up governance and trust layers (e.g., AGNTCY, SLIM) to monitor agent interactions and enforce organisational policies.
