TokenCast: Forecasting Token Consumption During LLM Agent Execution

Chaoqian Ouyang, Ling Yue, Libin Zheng, Huanghui Guo · Academic Institution · 28 Sep 2026

TokenCast predicts how many tokens a large‑language‑model (LLM) agent will use during a task, helping organisations estimate costs and manage resource limits before and during execution. The authors built a system that learns a cost profile for each execution segment and updates the estimate as the agent’s context grows. The result is a more accurate token‑usage forecast, reducing surprise cost spikes for cloud‑based LLM services.

HOW TO APPLY THIS

If you manage cloud LLM services, 1) monitor token‑usage forecasts from TokenCast to set API rate limits; 2) adjust your billing alerts based on predicted consumption; 3) use the forecast to optimise batch processing windows for cost efficiency.

Tracekit: Tamper-Evident Intent-Reasoning-Action Auditing for Autonomous Coding Agents

Bravish Ghosh · Academic Institution · 28 Sep 2026

Autonomous coding agents can modify files, run commands and spawn other agents without a tamper‑proof record, which makes it hard to audit their behaviour. Tracekit logs each session’s human intent, the model’s reasoning and the actual actions to a hash‑chained ledger that can be cross‑checked, giving an immutable audit trail. The system is open‑source, dependency‑free and already hooks into Claude Code’s lifecycle events.

HOW TO APPLY THIS

If you manage cloud infrastructure that uses autonomous coding agents, do the following: 1. Deploy Tracekit alongside your agents and enable its event hooks; 2. Store the resulting ledger on a secure, immutable storage (e.g. S3 with versioning or a blockchain oracle); 3. Periodically verify the hash chain against an external anchor to detect tampering.

MINT: Modeling GenAI Impact on Network Traffic

Andrew Nguyen, Samson Kempiak, Agrim Gupta, Koushik Kar · Academic Institution · 28 Sep 2026

MINT provides a data‑driven model of the packet traffic generated by generative AI workloads, fixing the gap where researchers had to fake AI traffic with unrelated services. The team built an end‑to‑end capture pipeline that logs real traffic from three large‑language‑model providers in a variety of network settings and then derives a traffic model from that data. The result is a set of validated, modality‑specific traffic profiles that can be plugged into network simulators to predict how GenAI will use bandwidth and affect scheduling.

HOW TO APPLY THIS

If you manage cloud infrastructure, here is what to do: 1. Export your existing network performance data to the MINT capture format. 2. Feed the captured traces into the MINT modelling tool to generate accurate GenAI traffic profiles. 3. Use those profiles in your capacity‑planning simulations to adjust bandwidth, QoS and routing for the expected GenAI load.

When Valid Tool Calls Change Meaning: Formation-Consistent Dispatch for LLM Agents

Geonwoo Kim, Brent ByungHoon Kang · Academic Institution · 28 Sep 2026

A new method called Formation‑Consistent Dispatch (FCD) stops a problem where the same tool call can later be executed with a different meaning because the system chooses a new implementation. It connects the call’s description to the authority that actually runs it, giving a proven record of what the call can do. The result is safer, predictable tool use that reduces security drift as systems evolve.

HOW TO APPLY THIS

If you manage cloud infrastructure, check how your orchestration platform routes external tool calls: 1) Map each call’s descriptor to the specific implementation that will run it. 2) Ensure that the implementation’s authority matches the declared permissions in the descriptor. 3) Audit the provenance log to confirm that no unexpected changes have happened during roll‑out or reconnect. This flags a risk: if your org uses automated tool agents, verify that your dispatch logic ties calls to verified implementations.

RSI-Router: Evolving Subtask-Level LLM Routing and Skills for Cost-Efficient Agents

Hao Li, Hangfan Zhang, Zhiyao Cui, Chunjiang Mu · Academic Institution · 28 Sep 2026

RSI‑Router solves the cost‑performance problem of running large language models (LLMs) by routing each sub‑task of a long‑horizon job to the smallest suitable model and continuously improving those routes. The authors built a recursive, self‑learning routing system that automatically assigns sub‑tasks to the right model and adds model‑specific skills as experience grows. The result is a significant drop in inference cost while keeping or improving overall task success rates.

HOW TO APPLY THIS

If you manage cloud infrastructure, use RSI‑Router to optimise your LLM workloads: 1) deploy a lightweight orchestration layer that monitors model performance and cost, 2) implement sub‑task routing rules that direct simple queries to small models, 3) enable the system to auto‑update routing policies based on usage data to keep costs low.
